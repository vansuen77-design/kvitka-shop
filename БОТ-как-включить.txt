БОТ-СПРАВОЧНАЯ В TELEGRAM
=========================================================

Что это. Тот же бот, который присылает заказы, научится отвечать
на команды: показывать заказы, покупателей и цифры за сутки.

Зачем. Админка закрыта наружу и открывается только через SSH-туннель.
Для управления это правильно, но чтобы просто глянуть с телефона,
сколько пришло заявок, поднимать туннель неудобно. Бот закрывает
ровно эту нужду.

Бот ТОЛЬКО ПОКАЗЫВАЕТ. Он ничего не меняет: ни статусы, ни товары,
ни цены. Даже если кто-то доберётся до бота, испортить он ничего
не сможет.


КОМАНДЫ
-------
   /zakazy        последние заказы
   /zakaz 12      что внутри заказа №12
   /segodnya      что везём сегодня
   /novye         только новые, ещё не в работе
   /pokupateli    кто завёл кабинет на сайте
   /svodka        цифры за сутки и неделю
   /ostatki       что заканчивается на складе
   /help          этот список

Русские названия тоже понимает: /заказы, /сводка и так далее.


КОМУ ОТВЕЧАЕТ
-------------
Только вам. Бот сверяет id отправителя с TELEGRAM_CHAT_ID из .env.
Сообщение с любого другого id отбрасывается молча — бот даже не
подтверждает, что он живой. Попытки видно в журнале:

    journalctl -u kvitka-bot | grep "чужого id"

Это важно понимать: имя бота может узнать кто угодно, но данные
получите только вы.


КАК ВКЛЮЧИТЬ (один раз)
-----------------------
1. Отправьте код на сервер: ОТПРАВИТЬ-НА-СЕРВЕР.bat
   Файл сервиса едет вместе с кодом.

2. Зайдите на сервер и выполните три команды:

    sudo cp ~/kvitka/deploy/kvitka-bot.service /etc/systemd/system/
    sudo systemctl daemon-reload
    sudo systemctl enable --now kvitka-bot

3. Проверьте, что поднялся:

    systemctl status kvitka-bot

   Должно быть "active (running)".

4. Напишите боту в Telegram:  /help
   Если пришёл список команд — всё работает.


ЕСЛИ НЕ ОТВЕЧАЕТ
----------------
Смотрите журнал:

    journalctl -u kvitka-bot -n 50 --no-pager

Частые причины:

  "В .env нет TELEGRAM_BOT_TOKEN"
      Токен не прописан на сервере. У сервера свой .env, отправка
      кода его не трогает. Открыть: nano ~/kvitka/.env

  "Conflict: terminated by other getUpdates"
      Бот запущен дважды. Так бывает, если оставили его работать
      ещё и на своём компьютере. Оставьте только сервер.

  Тишина, ошибок нет
      Проверьте, что пишете именно тому боту, чей токен в .env,
      и что ваш id совпадает с TELEGRAM_CHAT_ID. Узнать свой id:
      напишите @userinfobot.


ВЫКЛЮЧИТЬ
---------
    sudo systemctl disable --now kvitka-bot

Уведомления о новых заказах при этом продолжат приходить — они
работают отдельно, внутри самого сайта.
