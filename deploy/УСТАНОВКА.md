# Перенос КВІТКА на сервер

Инструкция для чистой Ubuntu 24.04. Все команды выполняются по SSH.
Времени — примерно час, из них половина ждать.

Как устроено после установки: наружу сервер не смотрит вообще, ни один
порт кроме SSH не открыт. Трафик приходит через туннель Cloudflare —
тот же самый, что работает у вас сейчас, просто запущен на сервере,
а не на компьютере. Домен и настройки DNS менять не нужно.

---

## 1. Купить сервер

Подойдёт самый младший тариф: 1–2 ядра, 2 ГБ памяти, 20 ГБ диска.
Система — **Ubuntu 24.04**. Windows не берите: он тут не нужен, стоит
дороже из-за лицензии, а его удалённый рабочий стол круглосуточно
перебирают паролями.

**Панель управления (Hestia, cPanel, ISPmanager) — не ставить.** Многие
хостеры предлагают её бесплатно, и она ставит свой веб-сервер, который
займёт порт и подерётся с нашим. Нужен чистый сервер, только ОС.

Заранее создайте у себя SSH-ключ — с ним вход надёжнее пароля:

    ssh-keygen -t ed25519

Жать Enter на все вопросы. Ключ окажется в
`C:\Users\vansu\.ssh\id_ed25519.pub` — это текстовый файл, откройте
Блокнотом, содержимое одной строкой вставляется в панели хостера.

Если хостер не даёт загрузить ключ при заказе, а присылает пароль root
на почту — ничего страшного, ключ добавим при первом входе:

    ssh root@АДРЕС_СЕРВЕРА          # пароль из письма
    mkdir -p ~/.ssh && nano ~/.ssh/authorized_keys
    # вставить содержимое id_ed25519.pub, сохранить Ctrl+O, выйти Ctrl+X
    chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys

Проверьте, что вход по ключу работает (новое окно, без пароля), и только
потом отключайте вход по паролю в шаге 2.

## 2. Первый вход и базовая защита

    ssh root@АДРЕС_СЕРВЕРА

    # обновить систему
    apt update && apt upgrade -y

    # отдельный пользователь для сайта: под root ничего не работает
    adduser --disabled-password --gecos "" kvitka
    mkdir -p /home/kvitka/.ssh
    cp ~/.ssh/authorized_keys /home/kvitka/.ssh/
    chown -R kvitka:kvitka /home/kvitka/.ssh
    chmod 700 /home/kvitka/.ssh

    # sudo для него
    usermod -aG sudo kvitka

    # firewall: снаружи открыт только SSH
    apt install -y ufw
    ufw allow OpenSSH
    ufw --force enable

    # автоматические обновления безопасности
    apt install -y unattended-upgrades
    dpkg-reconfigure -plow unattended-upgrades

Выключить вход по паролю (делайте, только когда убедились, что заходите
по ключу — иначе закроете себе доступ):

    nano /etc/ssh/sshd_config
    # PasswordAuthentication no
    # PermitRootLogin no
    systemctl restart ssh

## 3. Положить проект

С вашего компьютера, из папки `kvitka-server`:

    scp -r . kvitka@АДРЕС_СЕРВЕРА:/home/kvitka/kvitka

Дальше снова на сервере, уже под пользователем kvitka:

    ssh kvitka@АДРЕС_СЕРВЕРА
    cd ~/kvitka

    sudo apt install -y python3-venv python3-pip sqlite3
    python3 -m venv .venv
    .venv/bin/pip install -r requirements.txt

## 4. Настройки

    cp .env.example .env
    nano .env

Заполнить `SECRET_KEY` — сгенерировать так:

    .venv/bin/python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"

`ADMIN_ALLOWED_IPS` пока можно оставить пустым, вернёмся к нему в шаге 8.

## 5. База, переводы, статика

    .venv/bin/python manage.py migrate
    .venv/bin/python manage.py compilelocales
    .venv/bin/python manage.py collectstatic --noinput
    .venv/bin/python manage.py seed_catalog     # только если каталог пустой
    .venv/bin/python manage.py seed_pages
    .venv/bin/python manage.py seed_facets
    .venv/bin/python manage.py createsuperuser

Если переносите товары и фотографии с компьютера — вместо seed_catalog
скопируйте туда `db.sqlite3` и папку `media` из рабочей папки:

    scp db.sqlite3 kvitka@АДРЕС:/home/kvitka/kvitka/
    scp -r media kvitka@АДРЕС:/home/kvitka/kvitka/

## 6. Туннель

Скопировать на сервер файл с ключами туннеля — тот, что лежит у вас
в `C:\Users\vansu\.cloudflared\`:

    scp C:\Users\vansu\.cloudflared\ИДЕНТИФИКАТОР-ТУННЕЛЯ.json kvitka@АДРЕС:/home/kvitka/.cloudflared/

Поставить cloudflared:

    curl -L -o /tmp/cf.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
    sudo dpkg -i /tmp/cf.deb

**Важно:** пока сервер не заработал, туннель на компьютере не выключайте.
Один туннель может быть запущен в двух местах сразу — Cloudflare
распределит запросы между ними. Когда убедитесь, что сервер отвечает,
закройте окно `1-ТУННЕЛЬ.bat` на компьютере, и сайт останется только
на сервере.

## 7. Запуск

    sudo cp ~/kvitka/deploy/kvitka.service /etc/systemd/system/
    sudo cp ~/kvitka/deploy/kvitka-tunnel.service /etc/systemd/system/
    sudo cp ~/kvitka/deploy/kvitka-backup.service /etc/systemd/system/
    sudo cp ~/kvitka/deploy/kvitka-backup.timer /etc/systemd/system/

    sudo systemctl daemon-reload
    sudo systemctl enable --now kvitka
    sudo systemctl enable --now kvitka-tunnel
    sudo systemctl enable --now kvitka-backup.timer

Проверить:

    systemctl status kvitka kvitka-tunnel
    curl -I http://127.0.0.1:8000/          # должно быть 200
    journalctl -u kvitka -f                  # смотреть работу вживую

Теперь сайт поднимается сам после перезагрузки сервера и перезапускается,
если вдруг упадёт.

## 8. Доступ в админку

Узнайте свой адрес: откройте https://ifconfig.me — там одна строка.
Впишите её в `.env`:

    ADMIN_ALLOWED_IPS=91.203.10.55

    sudo systemctl restart kvitka

Откройте `https://kvitka.example/admin/` — должна появиться форма
входа. С любого другого адреса будет 404, будто страницы нет.

**Если адрес сменился** (провайдер выдаёт динамический — это обычное
дело), вы увидите 404 вместо формы. Тогда:

    journalctl -u kvitka -n 50 | grep Админка

В логе будет строка вида `Админка: отказано адресу 91.203.11.7` — это
ваш новый адрес, впишите его в `.env` и перезапустите сайт.

Чтобы не править каждый раз, укажите подсеть провайдера целиком:

    ADMIN_ALLOWED_IPS=91.203.10.0/24

Это чуть шире — внутрь попадут соседи по провайдеру, — но всё равно
отсекает весь остальной интернет.

**Запасной вход, работает всегда.** Даже с пустым списком адресов
в админку можно попасть через SSH — запросы с самого сервера проходят
без проверки:

    ssh -L 8000:127.0.0.1:8000 kvitka@АДРЕС_СЕРВЕРА

и, не закрывая это окно, открыть в браузере `http://127.0.0.1:8000/admin/`.
Так вы не запрёте себя снаружи, что бы ни случилось с адресом.

## 9. Резервные копии

Таймер уже включён: каждую ночь в 4:00 в `/home/kvitka/backups` ложится
снимок базы и архив фотографий, хранятся последние 14.

Сделать копию прямо сейчас:

    sudo systemctl start kvitka-backup

Забрать копии к себе на компьютер:

    scp -r kvitka@АДРЕС:/home/kvitka/backups C:\Users\vansu\OneDrive\Desktop\

Копии лежат на том же сервере — от сбоя диска это не спасёт.
Раз в месяц забирайте их к себе.

## Что делать дальше, каждый день

Правки по-прежнему в папке `kvitka-shop-КОПИЯ` на компьютере: запустили
`ЗАПУСТИТЬ-КОПИЮ.bat`, посмотрели на `http://127.0.0.1:8001/`,
понравилось — отправили на сервер файлом `ОТПРАВИТЬ-НА-СЕРВЕР.bat`.

Товары, цены и заказы ведутся прямо в админке сервера — их переносить
не нужно, они живут в базе на сервере.
