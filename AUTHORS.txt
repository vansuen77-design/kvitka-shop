WHAT THESE MARKS DO NOT DO
--------------------------
Honestly: a comment in the code is weak evidence by itself. Whoever
takes the code can erase it in five minutes.

The marks solve a different task — they show authorship to someone
who reads the code in good faith: a contractor, a buyer of the
project, a partner. A dispute needs something else, see below.


WHAT REALLY PROVES AUTHORSHIP
-----------------------------
1. The change history (git). Every commit is a date, a time and the
   content of the change. Faking someone else's history spanning
   several months after the fact is practically impossible. This is
   the strongest thing available, and it is free: a repository on
   GitHub or GitLab.

2. Drafts and correspondence. Early versions of files, tasks, chats —
   all with dates.

3. Original photos with the shooting date in the file properties.

4. Domain and hosting registered in your name: the hosting contract,
   the domain registration, the payments.

If the project is ever handed over or sold — do item 1 before the
handover, not after.
